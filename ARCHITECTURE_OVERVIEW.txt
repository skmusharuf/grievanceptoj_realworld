USER'S BROWSER
===============

    Home Page (/)
    ├── Loads: index.html
    ├── Styles: home.css + styles.css
    ├── Scripts: main.js
    └── Shows: Hero, Features, CTA Buttons

    Submit Complaint (/submit-complaint)
    ├── Loads: submit-complaint.html
    ├── Styles: forms.css + styles.css
    ├── Scripts: main.js, voice-input.js, form-handler.js
    ├── Features:
    │   ├── Text input fields
    │   ├── Voice input (Web Speech API)
    │   ├── Language selector (EN/HI/TE)
    │   └── Form validation
    └── On Submit:
        └── JavaScript calls → POST /api/complaints/submit → Backend

    Track Complaint (/track)
    ├── Loads: track.html
    ├── Styles: forms.css + styles.css
    ├── Scripts: main.js, tracking.js
    └── On Search:
        └── JavaScript calls → POST /api/complaints/track → Backend

    Admin Login (/admin/login)
    ├── Loads: admin-login.html
    ├── Styles: forms.css + styles.css
    ├── Scripts: main.js, admin-login.js
    ├── Step 1: Enter Email
    │   └── Calls → POST /api/auth/send-otp
    └── Step 2: Enter OTP
        └── Calls → POST /api/auth/verify-otp
            └── Stores session token in localStorage

    Admin Dashboard (/admin/dashboard)
    ├── Loads: admin-dashboard.html
    ├── Styles: admin.css + styles.css
    ├── Scripts: main.js, admin.js, Chart.js
    ├── Features:
    │   ├── Complaint table
    │   ├── Filtering (department, status, zone, search)
    │   ├── Charts (category pie, status doughnut)
    │   ├── Statistics cards
    │   └── Complaint details modal
    └── Calls:
        ├── GET /api/admin/complaints
        ├── GET /api/admin/departments
        ├── GET /api/zones
        ├── PUT /api/admin/complaints/{id} (status update)
        └── All with session token validation

DATA FLOW: SUBMITTING A COMPLAINT
==================================

1. User fills form in browser
   │
2. JavaScript validates form fields
   │
3. User clicks "Submit Complaint"
   │
4. JavaScript calls: GrievanceHub.apiCall('/complaints/submit', 'POST', data)
   │
5. Browser sends: POST request to Flask backend
   │
6. Flask receives: Request in complaints.py route
   │
7. Backend validates: Input validation
   │
8. Backend processes:
   ├── Stores complaint in database
   ├── Classification service: Categorizes complaint
   ├── Sends email confirmation
   └── Generates complaint ID
   │
9. Flask returns: {success: true, complaint_id: "CMP123456"}
   │
10. JavaScript receives response
   │
11. Browser shows: Success message with complaint ID
   │
12. User redirected to: /track?id=CMP123456


DATA FLOW: VOICE INPUT
======================

1. User clicks "Start Voice Input" button
   │
2. voice-input.js initializes Web Speech API
   ├── Creates SpeechRecognition instance
   ├── Sets language (en-IN, hi-IN, or te-IN)
   └── Enables continuous listening
   │
3. User speaks into microphone
   │
4. Browser captures audio
   │
5. Web Speech API processes audio
   ├── Recognizes speech
   ├── Converts to text
   └── Returns transcribed text
   │
6. JavaScript receives text
   │
7. Text appended to: <textarea id="description">
   │
8. User can:
   ├── Continue speaking (more text appended)
   ├── Stop voice (click button again)
   ├── Edit text manually
   └── Submit form normally


DATA FLOW: ADMIN DASHBOARD
==========================

1. User visits /admin/login
   │
2. JavaScript checks: Is session token in localStorage?
   ├── No → Show login page
   └── Yes → Redirect to dashboard
   │
3. User enters email
   │
4. User clicks "Send OTP"
   │
5. JavaScript calls: POST /api/auth/send-otp
   │
6. Backend:
   ├── Validates email (is admin?)
   ├── Generates 6-digit OTP
   ├── Saves to database
   └── Sends OTP email
   │
7. User receives OTP in email
   │
8. User enters OTP
   │
9. User clicks "Verify OTP"
   │
10. JavaScript calls: POST /api/auth/verify-otp
    │
11. Backend:
    ├── Validates OTP
    ├── Creates session token
    └── Returns admin info
    │
12. JavaScript stores:
    ├── Session token in localStorage
    └── Admin info in localStorage
    │
13. User redirected to: /admin/dashboard
    │
14. Dashboard loads complaint data:
    ├── JavaScript calls: GET /api/admin/complaints
    ├── Backend returns: All complaints
    └── JavaScript displays in table
    │
15. User can:
    ├── Filter by department, status, zone, search
    ├── View complaint details (modal)
    ├── Update complaint status
    └── See charts and statistics

CSS VARIABLE SYSTEM
===================

styles.css defines variables:

:root {
  --primary: #3b82f6;           (Button color)
  --bg-primary: #0f172a;        (Page background)
  --bg-secondary: #1e293b;      (Card background)
  --text-white: #ffffff;        (Main text)
  --text-light: #cbd5e1;        (Secondary text)
  --text-muted: #94a3b8;        (Muted text)
  --success: #10b981;           (Success color)
  --danger: #ef4444;            (Error color)
}

Used everywhere:

.button { background: var(--primary); }
.card { background: var(--bg-secondary); }
.text { color: var(--text-light); }

Change one variable → Changes everywhere!

SESSION MANAGEMENT
==================

localStorage stores:
├── adminSessionToken (from backend)
├── adminInfo (admin name, role, etc)

On page load:
├── Check if token exists in localStorage
├── If no → Redirect to /admin/login
├── If yes → Proceed to dashboard

On logout:
├── Clear both from localStorage
├── Redirect to login page

API calls include:
└── Session token in request headers
